# Reversible metadata representation

This unpublished v2 copies the original draft, replacing only the 11 JSON files flagged by unchanged default Gitleaks policy with `.derived.json` envelopes. All 44 findings were 64-character lowercase hexadecimal SHA-256 values, independently verified against seven exact source-S Git blobs. No allowlist or policy relaxation is used. Original raw receipts and the complete 411-leaf Linux archive remain unchanged outside this stage.

Each envelope records the absolute authoritative raw external path and its raw SHA-256. `metadata` preserves every JSON key, nonselected value, array position, and scalar type. Each selected SHA-256 scalar becomes `{"sha256_binding": index}`. `bindings[index]` contains its exact `original_field` path array (string object keys and integer array indices) and `sha256`. Replace each marker with that binding value to reconstruct the original parsed JSON. Every binding location and complete inverse equality were asserted. Parsed equality is not raw byte identity; original whitespace and serialization remain available in the bound external raw file. No signature or authentication claim follows from a hash.

`DERIVED-METADATA-MAPPING.json` binds raw and derived paths and hashes. Linux `TRACKED-SUBSET.json` enumerates raw versus derived representations and leaves full external manifest pins intact. Unconverted files are byte copies except the explicitly updated subset inventory and these new normalization records. Historical failed secret scan remains external and preserved. This stage is a review candidate, not a source commit or publication.
